### Added

- Direct Hermes accepts `--catalog-base-url` and `--catalog-api-key-env` for
  explicit private catalog reads, with no redirect or fallback and no catalog
  credential passed to Hermes. Canonical catalog defaults and direct wallet
  payment and verification checks remain unchanged.
- `flop hermes direct` launches Hermes on Linux/macOS through a wallet-funded local
  adapter with verified structured chat and tools, persistent request recovery,
  and explicit per-completion and lifetime escrow budgets. It never enrolls or
  calls the faucet. Chain transaction fees remain additional to those budgets.
- Direct Hermes waits for in-flight work during shutdown and uses a 20-minute channel lifetime.
- `flop model backup --source-pull` (#4237, draft; needs providers running `--self-ingest`)
  has the image's DA providers build their shards from the pinned Hugging Face revision, then
  pushes only what they still lack. The file table is always pushed.

- Scheduled `gateway renew` reads `GATEWAY_STATIC_MINERS_FILE` for operator-owned
  miner/catalog changes without a renewer restart.

- Model onboarding recognizes reviewed MXFP4 weight encodings while retaining BF16 registry
  and TOPLOC activation precision; generated metadata names the weight format `mxfp4`.
- `flop model release plan|status|resume|witness|acceptance`: one resumable release-onboarding workflow over
  the existing import/export/sign tooling, verified delivery and `flop model onboard`. It selects a
  reviewed profile from inspected content before weight transfer, keeps an immutable release journal
  outside the checkpoint, reconciles uncertain pushes by digest (an unavailable registry lookup is
  unknown and never authorizes a push), delegates capture/registration/DA/approval/paid admission to
  `flop model onboard` and host preparation to the managed controller, pins the onboard journal's
  chain genesis and publisher, reports registered, approved,
  disk/GPU-ready, calibrated, historical replay, current paid readiness and listing separately with
  the exact next action, and never lists a model without a separate catalog authorization.
- `flop model backup --unregistered`: places the DA backup of a pinned Hugging Face checkpoint
  before the model is registered, so the upload no longer waits for a capture GPU. The positional
  hash is the expected content-v1 root. The hub's table at the required `--source` and 40-hex
  `--revision` must reproduce it before any transfer. No model-registry write is made, and a
  registered model is refused.
- `flop model onboard --da-weights <commitment>`: a metadata run binds such a pre-placed backup.
  The image must be Leased at the measured size, and the file table naming it is derived and must
  be Leased with its custody placed. Both are checked before capture and read again before binding;
  a different bound or journaled image is refused.
- `flop model onboard --wait-capture <seconds>` polls the capture endpoint's `/health` for a 200
  before validating capture.

### Changed

- Depends on `@flop-labs/sdk` `^0.7.0`, which admits runtime spec 1,014,029 (candidate 1.14.29:
  ModelRegistry v4 stamp; 1,014,028 was never activated) and `1014021` through `1014027`.
  Published `0.5.0` resolves SDK `0.6.x`, which stops at `1014020`.
- `flop launch claude` and `flop launch codex` run against the public devnet
  gateway (`https://api.flop.network`, `--gateway` overrides) with the
  wallet-signed key from `flop agent credential`, and request that key's
  model unless `--model` is given. Claude Code uses the gateway's Messages API
  and Codex its Responses API through a launcher-owned `CODEX_HOME`
  (`~/.flop/codex-home`); both pin reasoning effort to `high`. Claude Code
  sends no pre-release body fields and caps output at 8,192 tokens, since the
  gateway reserves prompt plus maximum output against the key on every request. Arguments after
  `--` pass through to the agent (on Windows only arguments without spaces or
  shell metacharacters, since the agent starts through cmd.exe). Other networks, unknown agent types and a
  missing `claude`/`codex` binary now fail instead of falling back to the
  localhost demo key, `npx` or the PI agent; the key is never printed. A
  devnet trial key's quota is smaller than one Claude Code request, so
  `flop launch claude` needs a larger allowance to complete a turn.
- Public Hermes Desktop and authentication default to a supplied broker API key.
  Wallet trial enrollment requires `--payment trial`; broker failures never fall
  back to enrollment. Model selection respects the supplied key's scope.

- `gateway renew` no longer probes or withdraws a `tools` capability the record's serving
  profile binds; it names one still awaiting its one-time qualification instead.

- Native Windows rejects direct probe budgets before creating locks or changing budget state; the documented operator path runs direct probes in a Linux execution environment with durable file and directory sync.

- Direct gateway renewal requires an explicit persistent probe escrow/submission budget. Restarts and refunds do not reset authorization; transaction fees remain separately funded and outside the escrow ceiling. Receipt-only renewal remains available without a probe budget.

- `flop model onboard --paid-admission` clears `independent-audit-unavailable` when the stored
  replay completion is still current at the finalized head, records `paid-ready` and prints
  the readiness; it still opens no escrow and publishes no catalog. Stored completions now carry
  each turn's activation bytes; older artifacts fail closed.

### Deprecated

- `flop model onboard --soft` is a hidden no-op: every model now onboards without a TEE claim
  (#4339).

### Removed

- `flop model onboard --tee-platform` now fails with an explanation instead of registering a TEE
  claim. FLOP does not enforce TEE attestation, so onboarding always registers an empty
  `supported_tee_platforms` list and no longer refuses a registered model whose stored TEE list
  differs. TEE support is a roadmap item (#4339).

### Fixed

- `flop model backup` resumes read the model image once, for the push, instead of three times: the
  image's DA commitment and chunk layout are kept in the state dir (`image-commit.json`, 0600, atomic,
  versioned) and reused only when the revision, content_root, image size, file table, download
  receipt and every file's size/inode/mtime/ctime still match and the chain holds a Leased blob at
  that commitment. Anything else recomputes as before. A fresh run is unchanged.
- Preserve bounded, allowlisted direct-session failure and recovery diagnostics in CLI JSON,
  distinguishing finalized recovery rejection from unknown submission outcomes (#4193).
- The CLI container uses glibc for mounted operator `da-validator` binaries. Model backup,
  upload and DA-dependent onboarding probe `da-validator --help` before downloading weights or writing
  to the chain, with an explicit executable/libc error when the probe fails (#4234).
- Gateway renewal and `flop gateway allowlist` name the HTTP status of a failed unauthenticated `/session/info` probe and report
  5xx answers as an unavailable miner instead of a missing authentication check (#4085).
- Gateway renewal no longer withdraws a tailnet-hosted miner whose path is still on DERP: it disco-pings
  the node and re-reads tailscaled status for up to 10 s before failing closed on no direct path (#4085).
- A metadata-only `flop model onboard` run with `--registrar-keystore` no longer submits
  `set_model_admission_requirements` before any weights ref is bound. The registry rejects that
  call with `AdmissionWeightsRefRequired`, so the run used to end in a failed transaction. The
  requirements are now set by the run that binds or finds the DA backup.
- `flop model release status|resume` reads authenticated controller preparation completion
  for the current job and exact signed descriptor/runtime/profile before reporting disk-ready.
  Requests, legacy receipts and same-root sessions remain insufficient; restarts reverify caches.
- `flop gateway renew` keeps every earlier conformance pass that is still unexpired and still names
  a current catalog record's exact identity (slug, feature, registry version, model hash, decode
  policy hash), instead of rewriting the evidence file with only that run's passes. A model no
  longer drops out of the gateway catalog at the next renewer run while its last pass is valid.
  Entries are copied unchanged, so no expiry is extended; expired, re-identified or unparseable
  entries are dropped.
