### Added

- `serving_profile.py`: a decode policy can bind a text serving profile (context window,
  completion cap, tool-call parser, chat rendering profile) to the registered root through its
  `class_policy_hash`. The window defaults to the checkpoint's native `config.json` limit and can
  only be lowered; the parser comes from its chat template (`none` for no template or one with no
  tool handling; a template that reads `tools` or names a tool call in a format no verified parser
  covers fails derivation, so such a model has no profile until its format is supported). With such
  a policy the backend re-derives the profile from the served checkpoint and its loaded tokenizer,
  takes `MAX_MODEL_LEN`/`MAX_NEW_TOKENS` from it, refuses any other env value, and reports
  `serving_profile` in `/health`. Policies without a profile serve as before.

- `decode_witness.py` and `score_decode_witness.py`: offline TOPLOC witness tooling (#4043). The
  first captures, per prompt, the last prefill row and every decode row of native decode
  (serial or batched; batched rows split by the engine's own request layout), and the same
  positions from a prefill replay. The second scores those captures under last-token,
  per-token and per-32-token commits, with signed-exponent, upstream and exact-bit metrics, and
  hybrid serving's flattened top-k. Neither is copied into the image, and neither changes serving,
  lanes or any threshold.
- Inactive private MI300X ROCm qualification scaffold, pinned provenance, CPU runtime
  guards and isolated single-GPU pilot. The exact official vendor artifact has a
  separate source/byte identity guard and immutable launch contract; the derived
  image builds/imports on native x86; native-device acceptance remains pending.
- First versioned `miner-vllm-toploc` image for `linux/amd64`, built from the default backend target.
- Calibration corpus v2 (`derive_calibration.py corpus --version v2 --tokenizer …`, in
  `corpus_v2.py`). It has 1,536 synthetic rows in eight length buckets, cut to exact
  prefill lengths for one tokenizer, plus a token-count sidecar. v1 stays the default and
  reproduces byte for byte.
- `capture_calibration.py` prefills v2 random-id rows as `TokensPrompt`. On a v2 corpus it
  refuses, naming the rows, when a row is under 2 tokens, misses its `target_tokens`, or
  leaves no room under `--max-model-len`. It also refuses when `--batch-pairs` would not run
  the planned pair slots. The generation probe caps a row's decode at the room its prompt
  leaves under `--max-model-len`. `derive` reports per-class and per-bucket breakdowns and
  refuses a v2 corpus that has a bucket missing from either holdout half.

### Fixed

- `dense-gdn` target: prefill kernels run the first valid Triton config
  (`VLLM_TRITON_FORCE_FIRST_CONFIG=1`), so captures are reproducible across processes.
  Serving, calibration capture and replay refuse to start without it.
- Dense-GDN serving refuses prompts shorter than 2 tokens, and calibration capture refuses
  a corpus with any such row. vLLM 0.26 decodes them from an un-zeroed state slot.
- `replay_chat_activations.py` no longer passes on equal lanes alone. It reports the
  saturated-lane count and refuses a replay with any lane at the i16 clamp unless
  unquantised rows agree with zero exponent errors (#2168, #3224).
- `capture_calibration.py` no longer pairs rows with another run's metadata (#4297). A rerun
  without `--batch-pairs` removes a stale `<config>.alt.f32`. The previous `<config>.json` is
  removed before any rows are written, and the new one is written last through a temp file and
  `os.replace`. A crash mid-capture leaves no metadata, so `derive_calibration.py` refuses it.
